# {{title}}

## Problem
结合仓库证据描述当前问题，并关联跟踪 issue（如有）。记录受影响能力、可复现条件、当前结果及影响；附文件/符号/日志/场景等证据，避免只有主观判断。

## Goals
描述用户或维护者可观察的结果。每个目标应对应可验证的变化，避免把实现步骤写成目标。

## Scope
列出本次授权改变的行为、涉及能力和允许修改的项目相对路径。说明输入、输出或边界行为的变化；路径应足以支持任务拆分和所有权检查。

## Non-goals
列出相邻但本次不改变的行为，明确避免范围扩张。

## Acceptance
列出带稳定 ID 的场景（例如 `SCN-<CAPABILITY>-001-01`），描述前置条件、动作、可观察结果和可衡量边界。指标应能用测试、检查或用户可见结果判定。没有业务行为变化时，写明零 delta 的理由、证据以及为何维护结果仍可验收。

## Rules
none — 核对 `.workflow/rules.md`。引用规则时替换整段，使用 `- RULE-001: 满足方式与验证引用`，对其余规则逐项说明处置；无适用规则时保留 none 并说明依据。

## Open questions
- QUESTION-001 | unresolved | behavior | 写明尚未决定的行为、现有证据及其对范围或验收的影响；没有待决问题时将此行替换为 `none`。已解决问题应保留原格式并附决策证据引用。
