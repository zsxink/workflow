# 设计决策记录

日期：2026-10-21。以下为本方案的工程选择，后续调整须同步相应契约与示例。

## ADR-001：规格规范和引擎自研

用户最新决定：规格系统自行参考 OpenSpec、Spec Kit 等实现。采用自己的 formatVersion、AST、ID 和事务规则；不内嵌源码、依赖其 CLI 或维护多 provider。代价是规格解析、同步和兼容性都由 Workflow 负责，必须先完成冲突与失败 fixtures。

## ADR-002：单包、分模块

一个 npm 包先交付完整闭环，内部按领域分组。降低安装/版本组合成本。模块可演进为包，但没有实际独立生命周期前不拆 monorepo。

## ADR-003：主会话原生协作

当前宿主主会话为 Leader，CLI 为确定性工具。避免另一套模型启动器、凭据与会话管理。代价是不同宿主的原生工具、权限和可恢复能力必须单独验证，不能宣称终端命令能无人值守启动全部 Agent。

## ADR-004：Markdown 语义 + JSON 运行状态

规格/任务 Markdown 是人类协作的输入，runtime JSON 是机器状态，progress Markdown 是派生视图。任务完成状态可显示，但须核查证据。相对直接把 Markdown 当运行数据库，增加了视图重建；收益是明确原子更新、revision 和迁移语义。

## ADR-005：正式规格与 delta

长期规格与本次变更分开；稳定 ID + baseHash + ADD/UPDATE/REMOVE，UPDATE 替换整个 requirement。V1 不做自然语言 diff 自动合并。代价是同 capability 并行修改可能需要重基线，收益是冲突可检测且历史可追踪。

## ADR-006：运行态位于共享 Git 元数据

通过 common-dir 共享 run/lock，避免子 worktree 删除丢失运行证据，也不污染提交。代价是 clone 不带运行态；跨机器恢复以后通过显式导出/导入，不以隐式同步假装已支持。

## ADR-007：项目数据统一 `.workflow/`

规格、配置和管理资产统一命名，旧工具目录只作为未来 importer 输入。避免要求接入项目了解外部工具的隐式约定。代价是旧格式需要转换，正式文档不承诺兼容 OpenSpec/Spec Kit 命令。

## ADR-008：单版本本地 runtime

目标仓提交精确版本 runtime 和 managed assets，宿主入口不依赖全局最新包。代价是仓库增加构建产物；收益是 clone 可恢复、全局升级不改变运行语义。将来若改为本地依赖或独立二进制，应先定义新的安装与离线契约。

## ADR-009：默认 local，可选 GitHub

规格和执行协议无需远端账号。GitHub 仓库集成是可选能力；两个 profile 共用阶段和状态模型，最终完成事实不同。事项来源由 ADR-016 的独立 tracking 适配处理，是否强制关联由 tracking.required 决定，与仓库 profile 无关。

## ADR-010：事务 journal 而非整体原子承诺

跨文件归档/升级用 staging + journal + 互斥读写 + 恢复；单文件原子 rename 不等于全部原子。遇到外部新改动时保留现场并挂起，不为了回滚覆盖用户工作。

归档前同步主线并重验；归档后发现主线变化、最终检查失败或事项来源语义变化需要修订时，未集成分支通过受控逆向事务 reopen。已集成归档不可改写，已有 Git 提交通过后继提交修正。代价是多一种恢复操作，收益是当前 run 不会因活动输入已移动而陷入无路可续的状态。

## ADR-011：结构校验和产品授权分开

工具核查格式、依赖、引用和证据，主会话/用户判断语义与范围。会话已有授权可以记录后继续，不制造每阶段确认；范围扩张则重新取得授权并使相关指纹失效。

## ADR-012：独立不等于零运行环境

承诺无需其他规格/工作流产品或服务。Node、Git、宿主和项目自身构建工具为基础环境；普通解析库允许打包。独立二进制分发可后续扩展，不把跨平台零依赖承诺混入首版。

## ADR-013：以结构化证据推进阶段

Agent 输出是待核实声明，不直接作为阶段事实。派发回报采用绑定 run/dispatch/attempt 的版本化 JSON；验证项根据项目声明、变更影响和 CI 契约选择，并记录跳过理由。修复使受影响审查/验证失效，预算跨后继 run 保留。归档后强制核查完整规格投影、独立审查最终完整 diff、重跑所选命令；V1 不实现依赖语义等价判断的验证缓存。失败先受控 reopen 再修订。代价是增加最终验证成本与证据结构，收益是阶段推进可核查且恢复路径完整。

## ADR-014：TDD 在开发任务内部执行

可自动验证的行为变更和 Bug 修复采用 Red/Green/Refactor，先测试派发与实现派发分开；Tester 保留独立覆盖职责。以同测试内容、命令、环境和实现基线约束配对，不以任意非零退出码证明有效 Red。纯重构先补齐特征测试并通过，再以 verification 重构和回归；独立测试任务也使用 verification，确实不适用时经 spec-gate 记录 exempt 和替代验收。代价是增加命令执行及派发次数，收益是“先测试”的顺序可以核查，不能由最终测试全绿倒推。

## ADR-015：代码、规格与归档通过同一 Git 变更交付

独立变更分支承载 proposal/delta、实现、测试和最终规格归档。主会话可审计并提交开发检查点；归档更新只在同步 base、重验及文件事务后发生，归档提交前须最终检查。默认 merge 同步保留历史；不以 rebase/force push 修正已发布历史。已集成行为通过新 change 修订，未集成的失败归档通过受控 reopen 恢复。代价是分支中可能保留开发与恢复提交，收益是审查、恢复和规格历史可追踪。

## ADR-016：项目管理事项与仓库集成独立适配

需求来源使用 tracking 契约和平台无关 WorkItemSnapshot，首个 adapter 支持 GitHub Issues 只读接入；PR/CI/merge 留在 repository。连接身份、事项快照、采用内容与来源变化单独留证，来源状态不能代替授权或集成事实。配置支持多连接、change 首版只关联一个主事项，先不做自动关闭和状态回写。代价是同一平台有两类连接配置，收益是事项软件、项目空间与代码托管可以独立选择，后续增加项目管理适配不重写阶段协议。

## ADR-017：四宿主优先，使用当前会话的原生子 Agent

首批目标为 Codex、Claude Code、OpenCode、pi。主会话直接调用所在宿主原生工具，Workflow 只提供共享协议、任务包、入口/角色映射和确定性证据工具；不实现 Node.js Agent runner、模型 SDK 会话管理或 Agent CLI/RPC 包装器。宿主内语言和进程实现由宿主管理，Workflow 不接管模型运行循环。代价是具体版本缺少合规原生能力时不能自动补齐；收益是用户沿用宿主会话、权限及子 Agent 生命周期，避免第二套编排与凭据系统。pi 保留首批优先级，但官方子进程示例不作为合规实现，须单独验证原生机制。
